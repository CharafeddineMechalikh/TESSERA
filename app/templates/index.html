Parameters & Control

Generation runs a layer-streamed Qwen2 decoder whose KV cache lives on the workers. Every attention query is evaluated by all workers and merged with an exact float64 log-sum-exp, so the text is produced by the distributed attention path. Weights are streamed per layer, so decoding is much slower than a resident model: about 3 to 4 seconds per new token on this machine, so the 1000-token default can run for hours unless the model ends the sequence first or you press Cancel.

What this measures

Q/K/V tensors are captured from the pinned Qwen2.5-Coder-1.5B snapshot by an isolated capture process, then replayed through fresh HTTP worker processes that apply the certified omitted-mass pruning protocol. The dense reference is computed locally by the coordinator and is never sent to workers. When generation is enabled, a second worker cluster holds the KV cache and every attention query is evaluated there before the coordinator produces the next token.

Block bound

Cauchy-Schwarz 
centroid = mean(keys, axis=0)
radius   = max ||key - centroid||
bound(head) = (q[head] . centroid + ||q[head]|| * radius) * scale

Each worker holds a centroid and a radius for every unit, computed once when its shard is uploaded. The bound caps the contribution of a whole block, so a block can be skipped without reading its rows.

Omitted mass certificate

the pruning guarantee 
z_pruned  = gamma * sum over pruned unique tokens of exp(upper_bound - max_retained_score)
omitted   = z_pruned / (z_retained + z_pruned)
certified = 2 * v_max * omitted

The pruned mass is bounded rather than estimated, so the reported error is a certificate. The benchmark compares it with the actual error against dense attention, and a run fails if the actual error exceeds the certificate.

Exact merge

float64 log-sum-exp 
M = max_w m_w
weight_w = s_w * exp(m_w - M)
out = sum_w weight_w * o_w / sum_w weight_w

Workers return partial scores and outputs. The coordinator merges them in float64 with a log-sum-exp, so the distributed result equals the dense result to floating point precision, with or without overlapping ownership.

Protocol

request and response 
visible[key, query] = key_position <= query_position
scores  = einsum(q[query, head, :], keys) * scale, masked to -inf
lmax    = max over visible keys
out     = (exp(scores - lmax) @ values) / sum(exp(scores - lmax))

The full derivation, the FLOP accounting and the break-even rule are in the documentation site under Numerical protocol.
